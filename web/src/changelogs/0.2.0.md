All videos will now download with the mp4 container (more specifically, the .mp4 file extension). This is to avoid confusion when downloading video files that don't have the .mp4 extension (like .webm, which is usually provided by YouTube).

However, it's important to remember that using the .mp4 container doesn't actually fix any import errors in editing software (like Adobe). These are all issues with the video's codec.

All codec-related errors should be resolved by enabling the "Recode Video" mode in Edit > Settings > Video > Recode Video. However, this will increase download time because the server will have to re-encode the downloaded video.

For the next version, I plan to implement a strategy to download video files with the h264 codec first. At least that's a workaround.

Next up is the playlist media link.

Support for playlist links has actually been implemented in the backend extractor (part of the getInfo function) in this version, but I'm still having trouble deciding how the frontend (web) should process them. Should I give you the list of media in the playlist and let you choose for yourself?

In short, playlist links won't download at this time, like Instagram Caraousel.
